# 学习与更新

## 收到材料
确认真实文件或页面、标题、作者/发布者、版次或事件/发布日期、获取日期和场景。沿用已给资料，不重复索要。

先看目录，再围绕任务读必要完整页面、脚注、图表及上下文。记录 PDF 物理页；扫描件渲染查看，OCR 仅供检索，关键数字与语句回看原页。目录、简介或文件存在只能支持对应阅读状态。

各书按实际版次和扫描件各自登记。采用随包案例时，以卡片的印刷页码和版次定位；需要核对原句、数字或图表时，再读取对应原件。

## 拆解与提炼
书籍笔记用自己的话整理方法、理由、条件、例外和可执行检查，关联具体页码。原书留在本地，写作时只读相关部分。

案例记录品牌/产品、受众、目标、背景、渠道，可见表达与结构，作者声称的结果，以及自己的分析。结果附指标口径、周期与来源，缺失处保持未知。

区分真实投放、作者自述、写作练习、反面点评、假设重写和虚构示例。没有投放数据的改稿不成为“转化提升”证据；奖项、点赞、播放、点击、询盘与成交分别看待。

## 应用与改进
1. 已核对的作者方法登记 reference；自己的新推断登记 candidate，附适用条件和局限。
2. 在相关任务中用本产品事实应用，并记录方法 ID 与版本。
3. 只有收到真实反馈或可核对结果才新增 feedback。说明是编辑认可、交付验收还是市场效果；市场结果附指标、周期、原始出处。
4. 有证据时修正方法。validated 只在所记录范围成立；文字验收不证明成交提升。证据不足或冲突时保留原成熟度和缺口。
5. 更新增加版本，保存原因、旧版本与关联反馈。失效项可 retired；单个案例不改变整个岗位或用户品牌规范。

## 写入与核验
按 knowledge-contract 写入实际读过的内容。写前重读最新 catalog，增加 revision，先存旧版本到 history/catalog-r{旧版本}.json，再写变更；保留无关记录。并行学习由一位执行者合并最新差异。

原始文件不改动，新来源用新 ID。自己生成的示例不记录为成功案例。完成后运行 library.py validate --check-files，汇报实际新增/修改、定位、状态与未解决项。不能读写库时说明缺口，不声称已持久化。
